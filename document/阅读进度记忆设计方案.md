# 阅读进度记忆设计方案

最后更新：2026-05-02

## 1. 目标

当用户使用系统阅读书籍时，系统应记住用户上次读到的位置。用户再次打开这本书时，可以自动回到上次阅读的章节和滚动位置，而不是每次都从第一章开始。

这个功能要解决两个层级的问题：

- 章节级进度：知道用户上次读到哪一章。
- 章节内位置：知道用户在这一章里滚动到了哪里。

## 2. 当前项目现状

当前阅读页是：

- [BookDetail.vue](/abs/path/c:/Users/admin/Desktop/Book-Design/frontend/src/views/BookDetail.vue)

目前已有能力：

- URL 可以通过 `?chapter=12` 打开指定章节。
- 从素材库跳转时，可以通过 `?chapter=12&material=xxx` 定位原文。
- 阅读内容区域是 `.chapter-content`，该区域内部滚动。

目前缺少能力：

- 没有保存用户最后阅读章节。
- 没有保存章节内滚动位置。
- 再次打开书籍时，只能依赖 URL 参数，不能自动恢复用户真实阅读进度。

## 3. 恢复优先级

阅读进度恢复必须有明确优先级。

建议优先级如下：

1. `material` 参数优先级最高。
   示例：`/books/:id?chapter=12&material=xxx`
   这是素材定位场景，必须优先打开素材对应位置并高亮。

2. `chapter` 参数第二优先级。
   示例：`/books/:id?chapter=12`
   这是用户或页面明确要求打开某一章，应尊重 URL。

3. 已保存阅读进度第三优先级。
   如果没有 `material` 和 `chapter`，系统自动恢复上次阅读位置。

4. 第一章兜底。
   如果没有任何记录，则打开第一章或等待用户选择章节。

## 4. 推荐方案

推荐采用“服务端持久化 + 前端节流保存”的方案。

原因：

- 登录用户换设备后也能恢复阅读位置。
- 后续首页可以展示“继续阅读”。
- 书籍列表也可以显示每本书读到哪里。

不建议只用 `localStorage`，因为它只能在当前浏览器生效，和当前系统已有用户体系不太匹配。

## 5. 数据设计

新增一张表：

### `reading_progress`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String(36) | 主键 |
| `user_id` | String(36) | 用户 ID |
| `book_id` | String(36) | 书籍 ID |
| `chapter_order` | Integer | 最后阅读章节 |
| `scroll_top` | Integer | `.chapter-content` 的滚动距离 |
| `scroll_ratio` | Float | 当前章节阅读百分比，0 到 1 |
| `updated_at` | DateTime | 最近更新时间 |

约束建议：

- `user_id + book_id` 唯一。
- `user_id` 建索引。
- `book_id` 建索引。
- `updated_at` 建索引，用于首页展示最近阅读。

为什么同时保存 `scroll_top` 和 `scroll_ratio`：

- `scroll_top` 可以精确恢复当前视口。
- `scroll_ratio` 可以在字体、窗口大小、内容高度变化时做兜底恢复。

## 6. 接口设计

### 6.1 获取阅读进度

```http
GET /api/v1/books/{book_id}/reading-progress
```

响应：

```json
{
  "book_id": "uuid",
  "chapter_order": 12,
  "scroll_top": 840,
  "scroll_ratio": 0.42,
  "updated_at": "2026-05-02T12:00:00"
}
```

如果没有进度：

```json
{
  "book_id": "uuid",
  "chapter_order": null,
  "scroll_top": 0,
  "scroll_ratio": 0
}
```

### 6.2 保存阅读进度

```http
PUT /api/v1/books/{book_id}/reading-progress
```

请求：

```json
{
  "chapter_order": 12,
  "scroll_top": 840,
  "scroll_ratio": 0.42
}
```

行为：

- 如果已有记录，则更新。
- 如果没有记录，则创建。
- 只能保存当前登录用户自己的书籍进度。

### 7.2 阅读页状态

文件：

- [frontend/src/views/BookDetail.vue](/abs/path/c:/Users/admin/Desktop/Book-Design/frontend/src/views/BookDetail.vue)

新增状态：

```js
const restoringProgress = ref(false)
const progressLoaded = ref(false)
const pendingScrollTop = ref(0)
const saveProgressTimer = ref(null)
```

含义：

- `restoringProgress`：正在恢复进度时，不要立刻触发保存。
- `progressLoaded`：避免章节列表还没加载就恢复。
- `pendingScrollTop`：章节内容渲染完成后再应用滚动。
- `saveProgressTimer`：滚动保存节流。

### 7.3 初始化恢复逻辑

当前 [BookDetail.vue](/abs/path/c:/Users/admin/Desktop/Book-Design/frontend/src/views/BookDetail.vue) 已经在 `watch(chapters)` 中处理：

- `route.query.material`
- `route.query.chapter`

需要扩展为：

```js
watch(chapters, async (newVal) => {
  if (newVal.length === 0) return

  const materialId = route.query.material
  if (materialId) {
    await loadMaterialLocation(materialId)
    return
  }

  const order = Number(route.query.chapter)
  if (order && order >= 1 && order <= newVal.length) {
    await handleViewChapterByOrder(order)
    return
  }

  await restoreReadingProgress()
})
```

### 7.4 恢复阅读进度

在 [BookDetail.vue](/abs/path/c:/Users/admin/Desktop/Book-Design/frontend/src/views/BookDetail.vue) 中新增：

```js
const restoreReadingProgress = async () => {
  restoringProgress.value = true
  try {
    const progress = await bookApi.getReadingProgress(bookId)
    if (progress?.chapter_order) {
      pendingScrollTop.value = progress.scroll_top || 0
      await handleViewChapterByOrder(progress.chapter_order)
      await nextTick()
      restoreScrollPosition(progress)
    } else if (sections.value.length > 0) {
      await handleViewChapterByOrder(sections.value[0].chapter_order)
    }
  } finally {
    restoringProgress.value = false
  }
}
```

### 7.5 恢复滚动位置

因为章节内容在 `.chapter-content` 内部滚动，恢复时应操作 `chapterContentRef`。

```js
const restoreScrollPosition = (progress) => {
  nextTick(() => {
    const el = chapterContentRef.value
    if (!el) return

    const maxScroll = el.scrollHeight - el.clientHeight
    const scrollTop = progress.scroll_top || Math.round(maxScroll * (progress.scroll_ratio || 0))
    el.scrollTop = Math.min(scrollTop, maxScroll)
  })
}
```

### 7.6 保存阅读进度

在 `.chapter-content` 上监听滚动：

```vue
<div
  v-if="currentChapter"
  class="chapter-content"
  ref="chapterContentRef"
  @scroll="handleChapterScroll"
>
```

新增保存逻辑：

```js
const handleChapterScroll = () => {
  if (restoringProgress.value || !currentChapter.value) return

  if (saveProgressTimer.value) {
    clearTimeout(saveProgressTimer.value)
  }

  saveProgressTimer.value = setTimeout(() => {
    saveReadingProgress()
  }, 800)
}
```

```js
const saveReadingProgress = async () => {
  const el = chapterContentRef.value
  if (!el || !currentChapter.value) return

  const maxScroll = Math.max(el.scrollHeight - el.clientHeight, 1)
  await bookApi.saveReadingProgress(bookId, {
    chapter_order: currentChapter.value.chapter_order,
    scroll_top: Math.round(el.scrollTop),
    scroll_ratio: Number((el.scrollTop / maxScroll).toFixed(4))
  })
}
```

### 7.7 切换章节时立即保存

用户点击上一章、下一章、章节列表时，建议保存新章节进度。

在 `handleViewChapterByOrder` 完成章节加载后：

```js
if (!restoringProgress.value) {
  await saveReadingProgress()
}
```

注意：

- 刚进入页面恢复进度时不要保存，否则可能把旧进度覆盖成章节顶部。
- 从素材定位进入时也不要立即覆盖阅读进度，直到用户真实滚动或切换章节。

### 7.8 离开页面前保存

在 `onBeforeUnmount` 中补一次保存：

```js
onBeforeUnmount(() => {
  document.removeEventListener('mouseup', handleMouseUp)
  if (saveProgressTimer.value) {
    clearTimeout(saveProgressTimer.value)
  }
  saveReadingProgress()
})
```

## 8. 后端修改

### 8.1 `backend/app/models.py`

新增模型：

```python
class ReadingProgress(Base):
    __tablename__ = "reading_progress"

    id = Column(String(36), primary_key=True, default=lambda: str(uuid.uuid4()))
    user_id = Column(String(36), ForeignKey("users.id"), nullable=False, index=True)
    book_id = Column(String(36), ForeignKey("books.id"), nullable=False, index=True)
    chapter_order = Column(Integer, nullable=False)
    scroll_top = Column(Integer, default=0)
    scroll_ratio = Column(Float, default=0)
    updated_at = Column(DateTime, server_default=func.now(), onupdate=func.now())
```

需要从 SQLAlchemy 引入 `Float`。

建议补唯一约束：

```python
UniqueConstraint("user_id", "book_id", name="uq_reading_progress_user_book")
```

### 8.3 权限校验

两个接口都必须校验：

- 书籍存在
- 书籍属于当前用户
- `chapter_order` 属于这本书

如果 `chapter_order` 不存在，返回 404 或 400。

## 11. 边界情况

### 11.1 从素材位置进入

如果 URL 中有 `material` 参数：

- 先定位素材。
- 不要立即覆盖阅读进度。
- 用户滚动后再保存新进度。

### 11.2 从章节链接进入

如果 URL 中只有 `chapter` 参数：

- 打开该章节。
- 可以在用户滚动后保存。
- 不应立即覆盖为章节顶部。

### 11.3 章节被编辑

如果章节内容高度变化：

- 优先用 `scroll_top`。
- 如果 `scroll_top` 超出范围，用最大可滚动高度截断。
- 如果后续希望更稳，可以增加 `anchor_text`，但 MVP 不需要。

### 11.4 删除书籍

删除书籍时应同步删除该书的阅读进度。

在 `DELETE /api/v1/books/{book_id}` 中增加：

```python
db.query(ReadingProgress).filter(ReadingProgress.book_id == book_id).delete()
```

## 12. 实施顺序

### Phase 1：MVP

- 新增 `ReadingProgress` 模型。
- 新增获取/保存阅读进度接口。
- `BookDetail.vue` 打开书籍时自动恢复章节和滚动位置。
- `.chapter-content` 滚动时节流保存。

### Phase 2：体验增强

- 书籍列表显示“继续阅读”。
- 首页显示最近阅读。
- 支持阅读百分比展示。

### Phase 3：更精确定位

- 保存屏幕顶部附近的原文片段。
- 内容变化后通过文本锚点恢复更接近的位置。

## 13. 验收标准

完成后至少满足：

- 用户打开一本书，阅读到第 N 章中间位置后离开。
- 用户再次打开这本书，系统自动回到第 N 章和接近的滚动位置。
- URL 带 `material` 时，仍然优先定位素材，不被阅读进度覆盖。
- URL 带 `chapter` 时，仍然优先打开指定章节。
- 滚动阅读时不会高频请求后端，保存有节流。
- 换浏览器或换设备登录同一账号后，仍能恢复阅读进度。

## 14. 推荐结论

推荐把阅读进度作为服务端用户数据保存，而不是只存在浏览器本地。

MVP 只需要新增一张 `reading_progress` 表、两个接口，以及在 [BookDetail.vue](/abs/path/c:/Users/admin/Desktop/Book-Design/frontend/src/views/BookDetail.vue) 中增加恢复和节流保存逻辑。这样就能比较稳地实现“系统记得我上次读到哪里”。
