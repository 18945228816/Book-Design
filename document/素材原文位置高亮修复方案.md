# 素材原文位置高亮修复方案

最后更新：2026-05-02

## 1. 问题描述

当前有两个高亮场景都需要支持：

- 从素材库点击 `查看原文位置`，进入书籍阅读页后，对应原文片段必须高亮并滚动到附近。
- 用户主动打开一本书、进入某一章时，这一章中曾经记录过素材的位置也应该自动高亮，用来提醒用户这里已经被记录过。

现在的问题是：从素材库跳转到原文位置时，页面能进入对应章节，但对应文本没有稳定高亮；主动打开书籍时，也不能完整显示该章节所有素材位置。

## 2. 当前根因

结合当前代码，主要有四个原因。

### 2.1 跳转高亮被清空

文件：

- [BookDetail.vue](/abs/path/c:/Users/admin/Desktop/Book-Design/frontend/src/views/BookDetail.vue)

当前 `loadMaterialLocation(materialId)` 的逻辑大致是：

1. 先根据素材拿到 `selected_text`
2. 先把 `highlightText.value` 设为这个文本
3. 再调用 `handleViewChapterByOrder(loc.chapter_order)`

但 `handleViewChapterByOrder` 一开始会执行：

```js
highlightText.value = ''
```

所以从素材库传过来的目标高亮文本会被后续章节加载逻辑清掉。

### 2.2 当前只能高亮一个文本

文件：

- [BookDetail.vue](/abs/path/c:/Users/admin/Desktop/Book-Design/frontend/src/views/BookDetail.vue)

当前只有一个 `highlightText` 字符串。  
这意味着：

- 当前章节有多条素材时，只能高亮其中一条
- 主动打开书籍时，不能显示这一章所有曾经记录过素材的位置
- 从素材库跳转时，也无法把“目标素材高亮”和“其他已记录位置提示”区分开

### 2.3 主动打开章节时只取第一条素材

文件：

- [BookDetail.vue](/abs/path/c:/Users/admin/Desktop/Book-Design/frontend/src/views/BookDetail.vue)

当前 `loadChapterHighlights(chapterOrder)` 中只取了第一条素材：

```js
const first = items.find(m => m.selected_text) || items[0]
highlightText.value = first.selected_text || first.content.substring(0, 60).trim()
```

所以即使该章有多条素材，也只会显示其中第一条。

### 2.4 只依赖文本匹配不够稳定

只用 `selected_text` 做字符串匹配有两个问题：

- 章节中如果有重复句子，可能高亮错位置
- 如果以后章节内容被编辑，原文字串可能匹配不到

所以应优先使用 `anchor_start / anchor_end`，再退化到 `selected_text`。

## 3. 目标方案

要把高亮能力改成“双模式”：

- 定位模式：从素材库点进来时，重点高亮目标素材，并滚动到目标位置。
- 提醒模式：用户主动打开书籍章节时，高亮该章节所有已有素材位置。

两个模式使用同一套数据：

- `book_id`
- `chapter_order`
- `selected_text`
- `anchor_start`
- `anchor_end`
- `material_id`

## 4. 文件修改清单

### 4.1 `frontend/src/views/Materials.vue`

目标：素材库点击“查看原文位置”时，必须带上 `material` 查询参数。

当前已有的 `handleLocate(mat)` 应保持或调整为：

```js
const handleLocate = (mat) => {
  if (mat.book_id && mat.chapter_order) {
    router.push(`/books/${mat.book_id}?chapter=${mat.chapter_order}&material=${mat.id}`)
  }
}
```

检查点：

- 必须带 `book_id`
- 必须带 `chapter`
- 必须带 `material`
- 如果缺少 `material`，阅读页只能知道章节，无法知道要重点滚动到哪一条素材

### 4.2 `frontend/src/api/index.js`

目标：前端必须有素材定位接口。

确认 `materialApi` 中存在：

```js
getLocation: (id) => api.get(`/materials/${id}/location`)
```

如果缺少，需要加上。

### 4.3 `backend/app/models.py`

目标：素材表必须保存定位字段。

`Material` 模型需要包含：

```python
selected_text = Column(Text, nullable=True)
anchor_start = Column(Integer, nullable=True)
anchor_end = Column(Integer, nullable=True)
locator_text = Column(String(255), nullable=True)
```

如果本地数据库已经创建过旧表，只改模型不够，还需要做数据库迁移或手动补列。

建议补列：

```sql
ALTER TABLE materials ADD COLUMN selected_text TEXT NULL;
ALTER TABLE materials ADD COLUMN anchor_start INT NULL;
ALTER TABLE materials ADD COLUMN anchor_end INT NULL;
ALTER TABLE materials ADD COLUMN locator_text VARCHAR(255) NULL;
```

如果字段已经存在，不要重复执行。

### 4.5 `frontend/src/views/BookDetail.vue`

这是主要修改文件。

#### 4.5.1 替换单一 `highlightText`

当前：

```js
const highlightText = ref('')
```

建议改为：

```js
const chapterHighlights = ref([])
const focusedMaterialId = ref('')
```

`chapterHighlights` 保存当前章节所有需要高亮的素材：

```js
[
  {
    id: 'material-id',
    selected_text: '原文片段',
    anchor_start: 120,
    anchor_end: 168,
    content: '素材内容',
    status: 'completed'
  }
]
```

`focusedMaterialId` 表示从素材库跳转进来时，需要重点滚动和重点样式的那一条素材。

#### 4.5.2 改造章节加载函数

当前 `handleViewChapterByOrder(order)` 会清空高亮。  
建议改为支持参数：

```js
const handleViewChapterByOrder = async (order, options = {}) => {
  const { focusMaterialId = '', loadHighlights = true } = options

  chapterHighlights.value = []
  focusedMaterialId.value = focusMaterialId

  const res = await bookApi.getChapter(bookId, order)
  currentChapter.value = res
  expandSectionForOrder(order)

  if (String(order) !== route.query.chapter) {
    router.replace({ query: { ...route.query, chapter: order } })
  }

  if (loadHighlights) {
    await loadChapterHighlights(order, focusMaterialId)
  }
}
```

关键点：

- 不再用 `highlightText`
- 高亮加载必须发生在章节内容加载完成之后
- `router.replace` 要保留已有 `material` 参数，不要把它抹掉

#### 4.5.3 改造 `loadChapterHighlights`

当前只取第一条素材。  
建议改成加载当前章节所有素材：

```js
const loadChapterHighlights = async (chapterOrder, focusMaterialId = '') => {
  const res = await materialApi.getList({
    book_id: bookId,
    chapter_order: chapterOrder
  })

  const items = (res.items || []).filter(item => {
    return item.selected_text || (item.anchor_start != null && item.anchor_end != null)
  })

  chapterHighlights.value = items
  focusedMaterialId.value = focusMaterialId
}
```

注意：

- 不传 `material_status`，这样草稿和完成态都能提示
- 如果产品只想显示完成态，可以再加状态筛选，但“曾经记录过素材”更适合显示所有状态

#### 4.5.4 改造 `loadMaterialLocation`

当前问题是先设置高亮，再加载章节，导致被清空。  
建议改成先加载章节，再设置目标高亮：

```js
const loadMaterialLocation = async (materialId) => {
  try {
    const loc = await materialApi.getLocation(materialId)

    if (!loc.book_id || !loc.chapter_order) {
      ElMessage.warning('这条素材没有绑定原文位置')
      return
    }

    await handleViewChapterByOrder(loc.chapter_order, {
      focusMaterialId: materialId,
      loadHighlights: true
    })

    await nextTick()
    scrollToFocusedHighlight(materialId)
  } catch {
    ElMessage.error('无法加载素材定位信息')
  }
}
```

#### 4.5.5 替换 `renderParagraph`

当前 `renderParagraph(text)` 只能匹配一个字符串。  
建议改成支持多条高亮。

第一阶段可以用 `selected_text` 匹配：

```js
const renderParagraph = (text) => {
  let html = escapeHtml(text)

  for (const item of chapterHighlights.value) {
    const raw = item.selected_text || ''
    if (!raw.trim()) continue

    const escaped = raw.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
    const className = item.id === focusedMaterialId.value
      ? 'material-highlight focused'
      : 'material-highlight'

    html = html.replace(
      new RegExp(`(${escaped})`, 'g'),
      `<mark class="${className}" data-material-id="${item.id}">$1</mark>`
    )
  }

  return html
}
```

第二阶段再升级为 `anchor_start / anchor_end` 精确切片。

#### 4.5.6 新增滚动目标函数

```js
const scrollToFocusedHighlight = (materialId) => {
  nextTick(() => {
    if (!chapterContentRef.value) return

    const mark = chapterContentRef.value.querySelector(
      `.material-highlight[data-material-id="${materialId}"]`
    )

    if (mark) {
      mark.scrollIntoView({ behavior: 'smooth', block: 'center' })
    }
  })
}
```

如果没有找到目标 `mark`：

- 尝试滚动到第一个 `.material-highlight`
- 仍然没有则只停留在章节顶部，并提示 `未找到精确原文片段`

#### 4.5.7 修改 watch 初始化逻辑

当前 `watch(chapters)` 中已经处理了 `route.query.material`。  
建议保留这个入口，但调用新的逻辑：

```js
watch(chapters, async (newVal) => {
  if (newVal.length === 0) return

  const materialId = route.query.material
  if (materialId) {
    await loadMaterialLocation(materialId)
    return
  }

  const order = Number(route.query.chapter)
  if (order && order >= 1 && order <= newVal.length) {
    await handleViewChapterByOrder(order)
  }
})
```

这样：

- 从素材库进入：走定位模式
- 主动打开某一章：走提醒模式

#### 4.5.8 修改样式

当前 `.material-highlight` 只有一种样式。  
建议区分普通提醒和当前定位目标：

```css
.chapter-content :deep(.material-highlight) {
  background: #fff3bf;
  padding: 1px 2px;
  border-radius: 2px;
}

.chapter-content :deep(.material-highlight.focused) {
  background: #fef08a;
  box-shadow: 0 0 0 2px #f59e0b;
}
```

含义：

- 普通高亮：提醒这里有记录过素材
- focused 高亮：从素材库跳转过来的目标素材

### 4.6 `frontend/src/components/MaterialQuickCreateDialog.vue`

目标：选中文字快速记录时，要尽量保存锚点。

确认创建素材时传入：

```js
anchor_start: props.anchorStart,
anchor_end: props.anchorEnd,
selected_text: props.selectedText || undefined,
entry_mode: 'book_detail_selection'
```

如果 `anchorStart / anchorEnd` 是 `null`，也要保留 `selected_text`，后续还能用文本匹配兜底高亮。

### 4.7 `frontend/src/components/QuickEntryPanel.vue`

首页快速录入通常没有精确锚点。  
这里不要求必须高亮到具体文字，但要确保：

- `book_id` 必填
- `chapter_order` 必填
- 如果填写了 `selected_text`，阅读页可以用它做兜底匹配高亮

## 6. 验收标准

完成后至少满足：

- 从素材库点击 `查看原文位置` 后，会进入对应书籍和章节。
- 目标素材对应原文会高亮，并自动滚动到可见区域。
- 用户主动打开一本书的某一章时，该章已有素材位置会自动高亮。
- 一章有多条素材时，多处位置都会高亮。
- 从素材库跳转的目标素材应使用更醒目的 focused 高亮样式。
- 如果没有精确锚点，也能用 `selected_text` 做兜底高亮。
- 如果既没有锚点也匹配不到文本，至少打开对应章节并提示无法精确定位。

这个问题的核心修复点在 [BookDetail.vue](/abs/path/c:/Users/admin/Desktop/Book-Design/frontend/src/views/BookDetail.vue)：把“单个 `highlightText`”改成“当前章节的 `chapterHighlights` 列表”，并把“素材库跳转定位”和“主动阅读提醒”统一接到同一套高亮渲染逻辑上。
